## When editing can help
- Editing removes an obstacle that hides an ability; it does not add one. Go ahead only if a removable failure
  dominates and `acc when finished` is far above `acc`.
- Screened so far (`cases/screening`): loops dominate only in small Qwen3.5 models in thinking mode (0.8B strongly,
  2B moderately); Qwen3-0.6B/1.7B, Qwen3.5-4B, R1-Distill-Qwen-1.5B, SmolLM3-3B and Phi-4-mini-reasoning show no
  removable failure on GSM8K/MATH train (the post's Gemma 3 270M follow-up is the same negative case). On GSM8K,
  IFEval and MMLU-Pro: OpenReasoning-Nemotron-1.5B loops (13% of GSM8K answers); Qwen3-4B-Thinking-2507,
  LFM2.5-1.2B-Thinking, Granite-3.3-2B, Phi-4-mini, OLMo-2-1B, SmolLM2-1.7B and Qwen2.5-1.5B show only reasoning
  errors and unboxed answers.

## Method
- The loop edit: for each chosen layer, `W_down -= alpha * u (u^T W_down)[:, top-k]`, with `u` the residual
  direction separating loop continuations from normal reasoning (mean difference over matched pairs from the model's
  own correct traces) and the top-k MLP neurons writing most along `u`. Layers 15 and 19 of 24, k = 64, alpha = 6
  for both Qwen3.5 sizes; the 0.8B case reproduces the post's result independently.
- Contrast pairs (same prefix, normal vs failure continuation) give a direction stable across layers (split-half
  cosine > 0.9); the writer analysis localizes the edit, and within a model family the whole recipe transfers.
- **Selectivity on held-out pairs is a cheap pre-screen**: good edits lower the failure continuation's log-prob
  (~0.1 nats/token) and leave the normal one nearly unchanged (< 0.02); a drop of the normal log-prob predicts a
  loss in generation. It is not sufficient: on the loop-edited 0.8B, very selective loop edits still lost 6-10
  points in generation.
- Ablating a direction from the last layer's MLP hurts even when it is the largest writer: it is entangled with
  next-token prediction (a single gated unit there can still write a token-level change, see the "Wait" penalty).
- Dose is the main knob; larger models saturate at lower alpha. Adding layers does not help once the failure share
  is small.
- Always run a control with the same size of change: a norm-matched random orthogonal direction, or the same
  fitted values on random units. It separates a specific effect from a generic perturbation; it is not always null
  (random heads -3.1, shuffled fitted gains -4.1, a random direction at high dose -3.5), so measure it on DEV.
- **Selection noise.** At 100-250 problems x 1-2 samples the paired SE is 2-3 points, so the best of many variants
  on one DEV is inflated (DEV +7.8 / +6.5 confirmed at -0.6 / +3.0), and one confirmation set can mislead too (one
  edit: +0.8, +6.9 and +7.2 on three disjoint sets of 320 problems). Trust gaps of about 2 SE, add samples before
  choosing, and confirm once on a set no choice has seen (a subset of DEV is not one). A pooled gain
  can hide a loss on one task type: at ~32 problems per source the per-source SE is 5-8 points, so a per-source
  check needs more problems per source, and an accept/reject floor per source must scale with its SE.
- Before writing a decoding change into the weights (a logit bias, a forced close), measure it at decoding
  (`base@penalize=...`, `base@hint=...`): an edit that applies it everywhere should not beat it, so a larger gain is
  likely noise; only a gate that applies it where it helps can do better.
- Removing loops is not math-specific: the edits, selected on math practice only, lift IFEval, MMLU-Pro and BBH,
  where loops cost even more (2B: 41% of MMLU-Pro and 48% of BBH answers loop to the token limit; 0.8B: 91% cut on
  MMLU-Pro). It does not force early stopping: correct answers get longer, because harder problems now finish.
- Always measure the benchmark's failure kinds first: the loop share of a model differs a lot between benchmarks, so
  screening on math alone can miss a loop obstacle elsewhere.
- A teacher-forced answer start ("The correct answer is: \boxed{") is a fast screen (minutes) but overstates the
  effect for models that reason before answering: check the failure's share in real generation first.

## Fitting on the model's own answers (`wsp.fit`)
When the model solves a problem in some samples but not in others (pass@k well above accuracy) and no single
direction explains the failures, fitting gains on its own finished, correct practice answers moves it toward its
better samples. It sharpens what the model can already do: bounded by pass@k.
- Loop-ablated Qwen3.5-0.8B thinking (the published loop edit): per-unit MLP and per-head gains, fitted on ~900
  correct answers (4 samples per problem, 12k-token limit), three fits on 80% of the problems averaged, dose 1.25.
  On three disjoint practice sets of 320 problems x 2, none used for choices: +0.8 ± 1.7, +6.9 ± 1.9, +7.2 ± 1.8;
  pooled +4.9 ± 1.1, cut share 21% -> 14%. The gain is mostly math (+11.7 ± 2.0, answers that now finish), then
  MMLU-Pro +5.5 and GSM8K +4.2; instruction following +0.8 / +2.6. The same gains shuffled over units: -0.9 / -4.1.
- Another parameterisation on the same kind of data (gradient-refit output columns of ~650 MLP units, ~600 own
  correct answers) gave +6.4 ± 1.8 on its holdout; keeping only short answers did not matter (DEV +13.3 without the
  length filter vs +8.2 / +14.1 with it).

## Measure the behaviour ceiling before editing
An edit cannot add ability; it can at most make the model behave the best way the same weights already can. Measure
that first, without editing (`python -m wsp.case run <case> base@hint=<name> <set>` and other sampling overrides):
it bounds every edit and tells which benchmarks are worth an edit at all.
- Qwen3.5-2B thinking (after the loop edit): no hint or temperature helps, finished math answers are ~99% right and
  misses are hard problems cut at 32k (long reasoning, not loops). Merging with its Base checkpoint hurts both ways
  (lam -0.1: MATH500 -8.0). SAE features of doubt and backtracking (Qwen-Scope) are more active early in traces that
  end cut, but removing them costs MATH500 4.5-7.5 points: symptoms of hard problems, not habits. Qwen3.5-4B thinking
  is near saturated (AMC 95.6, GSM8K 96.0); LFM2.5-1.2B-Thinking never truncates.

## Tried and not confirmed (do not repeat without a new idea)
Paired gains on DEV128 / HOLDOUT256 after the loop edit (2B unless noted).
- **Effective temperature and structural loop breakers on the 0.8B thinking model**: final-norm x0.7-0.8 (T ~0.75;
  norms are not editable anyway) +0.4 / +1.4 on DEV128 x4: loops become long non-repeating reasoning, still cut.
  Gated-DeltaNet decay, key-input and MLP "repeat vs first occurrence" directions: no selective effect on real loops.
  A loop-onset direction from the loop-edited model's own traces, ablated from linear-attention outputs, trades
  verbatim loops for long deliberation (cut by loops 9 -> 1, other cuts 42 -> 58; HOLDOUT accuracy unchanged).
- **Conclude once the answer is found** (contrast `conclude`): DEV +1.6, HOLDOUT +0.8 ± 2.0. The direction is stable
  but the edit is not selective: it lowers the closing continuation too. After loop removal the 2B's remaining cut
  answers (18% at 32k tokens) are long non-repetitive reasoning, not a single removable behavior. On the
  loop-edited 0.8B, units that close the thinking early (by a settled answer, or steering toward "execute") gained
  1-1.5 SE on math and cost instruction following (-3 to -12, growing with the dose), even when built silent on
  instruction prompts. Closing only near the token limit did not: a unit reading the length (L10, rarely firing
  below 8k tokens) plus units opening the answer, chosen on DEV and run once on HOLDOUT, math +9.8 (cut 51% -> 4%),
  no source worse.
- **Damping copy heads against loops** (heads with the highest copy / normal ratio, `scale_cols` on their o_proj
  block, loop-edited 0.8B): the top 7 lose at every factor (-0.8 to -16 DEV); the best of ~25 variants (+2.7 ± 2.5)
  has neighbours from -2.3 to +0.4: noise.
- **Correct vs wrong reasoning** (contrast `correct`, Qwen3-0.6B, pass@8 96% vs pass@1 76%): split-half stability of
  the direction is negative (-0.15 to -0.39) and the separation < 0.55; "being right" is not one direction.
- **Second-guessing** (contrast `secondguess`: a wrong answer that had stated the right one, Qwen3-0.6B, 5% of
  samples): the direction is very stable (0.95) and separated, yet the edit is null at alpha 3 (-0.7 ± 1.4, random
  +1.1 ± 1.2) and harmful at alpha 6 (-5.8 ± 1.8, n = 8 per problem). The share is only 2-2.4% in Qwen3-1.7B,
  R1-Distill-1.5B and SmolLM3-3B. Even the prompt "trust a careful result" does nothing (-0.5 ± 1.3).
- **Prompt hints as the ceiling for baking a prompt into weights**: "keep reasoning concise" on the loop-fixed 2B
  gives +1.8 ± 1.0 (cut 18.6% -> 16.9%); too small to be worth writing into the weights.
- **Whole-model transforms on loop-free Qwen3** (0.6B, DEV128 x 8 samples): extrapolating post-training,
  `W + a (W - W_pretrained)`, a = 0.2 +0.1 ± 1.6 (1.7B -1.1 ± 0.9), a = -0.1 +0.3 ± 1.3, a = 0.5 runs away into long
  outputs; attention temperature (all q_norm x 1.1 / 1.25) +0.4 / +0.5; sampling temperature 0.4 -0.6; a logit
  penalty on "Wait"/"Alternatively" (thought switching) -1.4 ± 1.2 (R1-1.5B -0.6 ± 0.9). Their errors are reasoning
  errors; nothing global moves them. Where answers are often cut (loop-edited 0.8B thinking) the same penalty helps
  when gated: one last-layer unit writing it, read by an LDA with instruction prompts as negatives, DEV +5.3 ± 1.5,
  HOLDOUT +4.6 ± 1.5 (the holdout also entered its choice); ungated or stronger it leaks into instruction
  following (-3.1).
- **Too-short reasoning** (ThinkEdit's failure): absent here, short traces are the most accurate ones (0.6B 95%,
  R1-1.5B 100% vs 54% / 76% for traces over 6k characters).
- **Instruction following** (synthetic IF practice): the model already follows 94% of the checkable constraints,
  and its IFEval failures are scattered across constraint types.
- **Non-thinking mode** (0.8B): wrong answers are genuine reasoning errors, no removable failure. Qwen3-0.6B/1.7B
  already reason before answering; "reason step by step" moves MMLU-Pro / BBH by -3 to +3 (300 items), so there is
  no hidden "answers too fast" gap. Their "no answer" share (0.6B: 23-34%) is unboxed answers, a grader matter.
- **Decoding instead of weights**: repetition penalty 1.1 on the unedited 2B gives +11.7 ± 3.8 on DEV, the weight
  edit +17.2 ± 3.7; the edit is better and needs no change to the sampler, but most of the loop gain is reachable
  by decoding.

## Engineering
- One job per GPU (tools/queue.sh starts a worker per GPU, so N GPUs run N experiments at once). One 24 GB GPU: vLLM startup ~4 min; a looping 0.8B at 32k tokens ~3,000 tok/s (128 problems ~15-30 min,
  MATH-500 ~1.5 h). Probes take minutes.
- Compare edits only paired; unpaired passes of 128 answers are ~4 points noisy.
